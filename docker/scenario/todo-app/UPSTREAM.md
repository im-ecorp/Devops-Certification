## Local maintenance refactor

Only current code is retained. Pre-refactor snapshots and cached source copies were deleted at the user’s request.

- Dependencies: React/DOM 19.3, Bootstrap 5.3.8, Font Awesome 7 with React wrapper 3.5, Vite 8/plugin 6, ESLint 10 flat config, Jest 30, Express 5.3, mysql2 3.24.5, SQLite 6.0.1 and fresh transitive resolutions. Node 24 LTS is the tested runtime. React Bootstrap remains stable 2.10.10. UUID remains compatible CommonJS 11.1.1; latest 14 is not needed for this API. TypeScript 6 is only a linter peer dependency; 7 is outside the parser's supported peer range. No TypeScript rewrite was made.
- React/API fixes: initial list loading validates status/shape and offers Retry on failure; functional list updates avoid stale state and missing-ID slice corruption; failed create/update/delete requests no longer mutate the visible list and show retryable errors; ineffective React 19 function `propTypes` were removed. Deprecated regular icon imports now use maintained SVG packages. Bootstrap is imported as distributed CSS, avoiding deprecated Sass internals without modifying vendored code. Only the active `eslint.config.js` configuration is retained.
- MySQL fixes: decode `_FILE` settings as UTF-8 strings without changing password contents; select MySQL for `MYSQL_HOST_FILE` alone. Schema and query semantics are unchanged.
- Tests: add real-source UI regressions, MySQL driver-boundary tests, and an actual Express/SQLite HTTP CRUD smoke test. Existing SQLite tests now use in-memory data and close connections instead of unlinking a default DB file. Remove unused SQLite variables and a Yarn-only `resolutions` field npm never honored.
- Unchanged boundaries: root Compose/DB image, `todo-db-data`, API URLs, loopback `127.0.0.1:8092`, database schema, existing credentials and architecture. The license remains intact. Superseded upstream Dockerfile, development Compose and upstream README were removed; use the root README/Dockerfile for maintained commands.

See [`VALIDATION.md`](VALIDATION.md) for results and residual advisories. No git staging/commit or deployment was performed.

## Selection

The [official `docker/getting-started-app`](https://github.com/docker/getting-started-app) (inspected at `6b025fc53bc7b9bef435d6b09bcd1da5a871c9cc`) is a smaller Express/SQLite/MySQL tutorial app, but has no checked-in Dockerfile or Compose in its repository root. This source has a React client, Node API, tests, lockfiles, multi-stage Dockerfile and a development Compose stack, making it a more complete source-based Compose exercise. We run its `final` image target with MySQL rather than its development proxy/Vite/phpMyAdmin stack.

## Differences from the upstream development setup

Upstream Compose uses Traefik with a Docker socket, public port 80, phpMyAdmin, watch-mode services, root DB account and example plaintext credentials. This lab uses a single built frontend/API container, private DB network, loopback-only port 8092, named DB volume, non-root Node runtime, health probes, and generated local credentials. No Docker socket or DB/admin UI is mounted or published. The old development Compose definition is no longer included.
